# 「我的」整页设计提案

设计日期：2026-10-23。状态：用户已批准自然留白方案，原生页面已实施；设备验收待重新Run。

[打开高保真 HTML 设计稿](mine-redesign-2026-10-23.html)

设计由移动端 UI Designer 角色完成，应用 `ui-ux-pro-max` 的原生布局、Dynamic Type、触控与浅深主题指导。设计以当前 `MineView` 和真实 `HomeTheme` 为基础；技能数据库返回的通用网站 Hero/CTA、蓝紫配色和外链字体均不适合本项目，未采用。设计稿阶段只交付HTML与规格；用户批准后由主代理实施 SwiftUI 页面，设计师复核源码及静态渲染。

## 方向比较

| 方向 | 视觉与结构 | 优点 | 取舍 |
| --- | --- | --- | --- |
| **A · 自然留白，推荐** | 白色身份区与页面连成一体；活动两列；薄荷绿俱乐部卡；账户服务分组 | 身份清晰、扫描快，保留首页森林绿；头像与卡片有层级，适配成本低 | 默认字号下活动入口不展示计数；大字号改单列 |
| B · 森林名片 | 深绿身份卡占据首屏，下面接相同分组 | 品牌感更强，头像与昵称醒目 | 顶部视觉重量偏高，与首页活动主卡容易重复；长昵称更易挤压 |
| C · 原生简洁 | 平铺头像行，活动与服务全部用系统分组列表 | 熟悉、可读性强、实现最直接 | 入口较多，纵向更长，个人中心辨识度偏弱 |

推荐 A：真实身份是主角，活动是快捷操作，俱乐部是上下文，账户服务是工具。保留所有现有入口，不新增会员等级、积分、在线/认证标签、虚构统计或资料编辑。

## 推荐结构

1. 原生「我的」导航栏；右上设置，触点 44 × 44 pt。
2. 身份区：72 pt 头像、真实昵称、账号与复制按钮、我的二维码。
3. 我的活动：我的报名、候补记录、签到记录、已参加活动；默认 2 × 2。
4. 俱乐部：当前俱乐部名称与详情入口、独立的更换俱乐部行。
5. 账户与支持：黑名单、投诉与支持。隐私与安全入口已按用户后续要求移除。
6. 既有四栏 Tab；「我的」保持选中。

设置保留右上入口，不在底部重复增加同名行。退出登录、注销继续留在现有设置页。本设计仅覆盖「我的」主页面；二级设置中的历史演示身份需单独修复，不能因为本稿而当作已完成。

## 数据与交互合同

| 组件 | 数据来源 / 实际行为 | 本稿处理 |
| --- | --- | --- |
| 昵称 | `UserSessionStore.currentUser.nickname`；为空取当前账号，再为空为「未设置昵称」 | 用「昵称示例」演示，不借用历史演示会员名 |
| 账号 | 同一用户的 `userName`；没有值不造账号 | `account_demo` 为公开示例；长账号换行 |
| 头像 | 当前 `avatar` → 既有 `RemoteAvatarURL`、文件 Host、Kingfisher 与旧图片处理器 | 本地 SVG 占位，无外链图片；加载失败保持同尺寸占位 |
| 复制账号 | 仅当前真实账号非空时可用；复制后沿用居中 Toast「账号已复制」 | 点击只显示预览说明，未访问剪贴板 |
| 我的二维码 | 复用 `BusinessQRCodeView`、共享 `ContactsBusinessStore`，`groupID: nil` | 不生成假二维码；HTML 只演示入口 |
| 四类活动记录 | `RecordKind` 原有值路由和 `RecordsScreen` | 全部保留；不把 `ClubStore` 的本地示例数量当作真实统计 |
| 当前俱乐部 | `ClubHomeDestination.club`，当前仍是本地演示内容 | 使用现有「远山户外」；画板外明确标注其演示性质 |
| 更换俱乐部 | 原确认框 → `store.signOut(changeClub: true)` → 邀请码页 | 保留确认与取消；不把卡片点击等同于切换 |
| 黑名单 | 原 `SafetyRoute.blacklist` | 继续使用真实 SDK 列表 |
| 投诉与支持 | 原 `ComplaintView(target: .general)` 与提交反馈 | 不扩展为客服会话、工单或反馈统计 |
| 设置 | 原 `SettingsScreen` sheet | 只重新设计导航入口，不改二级页面 |

已接入的顶部真实资料逻辑必须原样保留。不得再从 `ClubStore` 演示会员取昵称、头像或账号，不另建用户缓存；UID 变化需沿用现有头像身份重建，文件 Host 变化需重新解析。主页面不新增用户资料请求或轮询。

二维码只是现有能力在身份区的便捷入口，不增加生成接口。最终接线必须留在现有导航所有者中，保证 push 时 Tab 隐藏、返回时恢复，不能新建孤立 `NavigationStack` 或第二份业务 Store。

## 视觉规格

### 色彩

沿用 `HomeTheme` 语义色，不扩散旧 `ClubTheme` 的固定浅色值。主页面应使用可自适应的背景与卡片；若现有 `ClubScroll` / `ClubCard` 不能按页配置，优先在本页组合布局，避免改全局共享组件影响其他页面。

| Token | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| background | `#F7F7F2` | `#151D19` | 页面背景 |
| surface | `#FFFFFF` | `#202D25` | 身份区、活动、菜单 |
| text | `#20392D` | `#F0F5EC` | 昵称、主要入口 |
| secondaryText | `#58665C` | `#B9C9BD` | 账号、分组名、辅助文字 |
| forest | `#285B43` | `#AED5B5` | 图标、复制、二维码、选中 Tab |
| mintSurface | `#E6EDE2` | `#2B4031` | 俱乐部卡、图标衬底 |
| border | `#D8DED5` | `#425449` | 细边界与分隔 |

按相对亮度公式计算：主文字/表面浅深分别 12.47:1 / 12.97:1；辅助文字/表面 6.05:1 / 8.30:1；辅助文字/薄荷底 5.07:1 / 6.46:1；森林绿/表面 7.87:1 / 8.87:1。上述文字组合达到 AA 普通文字对比度目标。细分隔线仅分组，不是唯一的操作识别边界；文字、图标与箭头共同明确入口。该计算不是完整 WCAG 或 VoiceOver 验收。

### 字体、尺寸与节奏

- 字体：iOS 系统字体，中文使用系统 PingFang；不外链品牌字体。
- 导航 17 pt / semibold；昵称基准 24 pt / semibold；菜单 15–16 pt；活动 14–15 pt；辅助文字 12–13 pt。生产实现用相对文本样式，不能照搬 HTML 的固定字号。
- 主内容两侧 20 pt；身份区两侧 24 pt；卡内 16 pt；分组间 24 pt；标题与内容 12 pt。
- 头像 72 × 72 pt、24 pt 连续圆角；身份区下沿 28 pt；活动/俱乐部/菜单卡约 22 pt 连续圆角。
- 活动默认每项最低 64 pt 高；菜单默认最低 56 pt，按文字增高；复制、二维码、设置与更换入口均至少 44 pt。
- 菜单图标 20–22 pt；活动图标 20 pt / 34 pt 衬底；仅用同一线宽与圆角风格。最终优先匹配 SF Symbols，HTML 内联 SVG 只为设计示意。
- 页面内无投影叠层、渐变光效或装饰性轮播；画板外手机阴影不属于产品 UI。

## 窄屏、大字号与状态

- 390 pt：身份横排，活动两列；默认字号视口中不足的内容可纵向滚动，固定底栏不覆盖最后一行。
- 375 pt：保留 20 pt 边距；昵称、账号、俱乐部名允许自然换行，文本容器可收缩，复制按钮不被挤出边界。
- 辅助字号：身份改纵向；四类活动改单列；行高由内容决定，图标不压缩文字。优先依据 `dynamicTypeSize.isAccessibilitySize` 与 `ViewThatFits` 决策。
- 长账号不通过缩小字号保持单行；VoiceOver 朗读完整值。没有编辑功能时，不在头像或整块身份上放导航箭头。
- 头像请求中保持占位和固有尺寸，更新不改变布局。仅头像失败不阻塞整页，不出现全屏重试。
- 用户资料清空：不残留前一账号；短暂显示「未登录」，隐藏账号复制和二维码，随后由现有路由处理，不在该页自行恢复认证。
- 同一会话资料刷新保留已知资料；不因刷新添加占位骨架或整体抖动。记录计数不显示，本轮不新增统计加载状态。
- HTML 的「大字号」是 375 pt 布局压力示意，不是原生 Dynamic Type 的逐级精确复刻；其长俱乐部名亦为专门的溢出示例。

## 原生实现与验收边界

最终实施建议保留 `MineView` 的资料观察、会话与页面状态所有权，将私有视图组合拆成身份区、活动入口、俱乐部卡、服务分组；不要提前建立通用设计框架。导航栏继续 `.navigationTitle` / `.toolbar`，底栏仍由现有 Tab 和 `ActivityNavigationScope` 管理。支持 iOS 16，不使用 iOS 17 Observation 或 iOS 26 Liquid Glass。

按压仅改变背景或透明度，不改变组件尺寸；复用系统导航转场，遵循减少动态效果。所有图标按钮有标签，装饰图标对 VoiceOver 隐藏；阅读顺序为身份 → 二维码 → 活动四项 → 俱乐部 → 服务。设置由导航栏标准位置访问。卡片内部各按钮独立，不嵌套可点区域。

实施后需要：浅深主题、375/390 pt、横屏/宽屏、最大辅助字号、VoiceOver、按钮触控区域、资料刷新/退出切账号，以及所有既有路由返回行为的原生验证。HTML 仅证明可审阅的布局方案；不代表 SwiftUI 实现、原生屏幕阅读器或真实服务端链路已验收。

实施已完成于 `MineView.swift` 与 `Components/MinePageContent.swift`。真实身份、复制账号、二维码及全部原有入口已接线；无签名iOS构建和会话维护17项、角色/资料26项、SDK会话隔离7项回归通过。设计师复核五张生产展示组件静态图未发现裁切、重叠或阻断性拥挤。静态图由macOS宿主适配渲染，辅助字号图只验证布局分支，不能证明iOS真实字号、VoiceOver、导航安全区与触控效果。未操作设备，原生运行验收仍按上一段执行。
