## 1. 用户价值与范围

用户可以在 ddlNew 聊天底部直接发起语音或视频通话，与同一服务器上的旧客户端互通；单聊直接呼叫对方，群聊选择成员、接受邀请或加入已有群通话。离开通话全屏后仍可通过浮窗回到当前通话，在任意已登录页面收到来电。通话沿用 xgd 的信令、系统配置和媒体三方库，呈现遵循 ddlNew 的森林绿主题与 UIAdapter。

本轮覆盖单聊、群聊、呼出、应用内来电、完整通话页、音视频控制、成员邀请、已有群房间加入、最小化恢复及登录生命周期。两种供应商均属本轮范围。源工程未在本次核对的通话链路中实现 CallKit / PushKit；本轮不新增系统电话界面、进程被杀后的 VoIP 唤醒、屏幕共享、通话录制或美颜。网络重连使用原 SDK 能力，不能把离线 UI 演示称作双端通话成功。

验收目标：下文全部必需用例按 LiveKit / Zego、语音 / 视频、单聊 / 群聊适用组合通过；任何尚未运行的设备用例均明确标记待验。没有现成线上成功率基线，不填写虚构比例。

协议映射必须保持：

| 动作 | LiveKit | Zego |
| --- | --- | --- |
| 发起单聊 | `to_id`，mode 语音1/视频0 | `callType` Voice/Video，`chatType` SINGLE_CHAT，`friendIds` |
| 发起群聊 | 群 `chat_id`、被邀数组 `to_id`、mode | GROUP_CHAT、`groupId`、`friendIds` |
| 标识 | `hash` | `callId` |
| 未接通取消 | discard `reason="cancel"` | `imSdkUserCancelCallWith` |
| 未接通拒绝 | discard `reason="refused"` | `imSdkUserRejectCallWith`，旧业务 `discardType="refuse"` |
| 接通后挂断 | discard `reason=""` | `imSdkUserHangUpCallWith` |
| 群追加邀请 | `hash` + `user_id` | `callId` + `friendIds` |
| 查询群现有通话 | `chat_id` | `groupId` |

LiveKit `mode` 与新端通用音视频枚举、Zego 消息 `callType` 不是同一数值合同，必须显式转换，不直接 rawValue 互传。

LiveKit 单聊 discard reason：`disconnect` 中断、`missed` 无应答、`cancel` 主叫取消、`refused` 拒绝、`accept` 其他设备已接听、空串正常结束。群成员 `refused` / `timeout` 只影响该成员，本人超时才关闭本端。Zego 群状态：3超时、4拒绝、5挂断、6接受、7中断、8其他设备已接听、9追加邀请、10主动加入、11房间结束、12加入房间超时。必须同时核对会话身份、房间标识、群 ID 和操作成员，不能见到任意结束通知就全局关闭。

接口建议：业务视图只读通话快照并提交 start/accept/reject/end/mute/speaker/camera/invite/join/minimize/restore；不让 SwiftUI 每次重绘创建 SDK 房间。协调器保存会话身份、供应商、房间标识、通话类型、参与者和连接阶段；供应商适配负责各自字段和实际媒体操作。媒体 SDK 的房间/track 不进入可持久化模型。每个异步回调核对“认证轮次 + 本次通话轮次 + 房间身份”。

状态至少区分 idle、preparing、outgoing、incoming、accepting/connecting、connected/reconnecting、ending；“全屏/最小化”是呈现状态，不是新的通话。仅 SDK 实际连接对应事件推进 connected。建立请求尚未回执就取消时，迟到返回的已创建房间需按原轮次补偿清理，不可重新呈现。

## 7. 需求证据与旧端缺陷的边界

- 旧 `NoaChatInputFunctionView` 仅明确 `"1"` 才展示通话，而动作方法只对明确 `"0"` 返回；新端统一为有效开启后可用，避免缺失配置意外调用。
- 旧 LiveKit 某些群创建参数默认 camera open，但媒体类型仍应约束采集；迁移必须保证语音通话无相机采集。
- 旧 Zego 忙线不会主动发送拒绝；保留协议差异，不能自行增加未证实的 `"busy"` 值。
- 旧 Zego `onRoomStateChanged` 多个错误 case 只有注释；新端不能照搬空处理后声称弱网和失败恢复完成。
- 旧 AppDelegate 部分 LiveKit 全局终态没有严格房间匹配；新端必须保留现有认证轮次并增加通话身份匹配，避免老房间事件关闭新通话。
- 旧选人页没有证实固定成员上限；布局容量不能替代业务限制。
- 来电和最小化是两种不同视图：来电尚未接听，最小化承载既有通话。测试不能用其中一种代替另一种。
