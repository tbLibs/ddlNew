# 我的：网络检测与关于我们

## 目标与入口

在“我的 → 账户与支持”增加“网络检测”和“关于我们”，沿用当前森林绿、浅深色、原生返回、大字号及至少44pt触点。保留当前工作区活动／俱乐部迁移结果；xgd仅作只读参考。

## 对照结果

- xgd Mine 将当前企业邀请码传入 NoaNetworkDetectionVC。
- 检测分为网络连接情况、节点获取检测、服务器连接检测，展示进度、耗时、成功／失败明细和重试；页面关闭取消等待，迟到结果按检测轮次隔离。
- DNS1诊断不使用旧连接缓存掩盖本轮失败，依次主域、备域、BIN；节点通过独立TCP/ECDH探测验证。xgd随后还会退回旧五路解析及OSS导航。
- ddlNew目前生产连接明确只使用DNS1，旧五路及OSS Auth兜底已删除。诊断不能把TCP/ECDH成功显示成登录AUTH成功。
- xgd关于页面实际显示当前App图标、版本／build、服务协议、隐私政策。评分、更新及日志上传方法没有当前可见入口，不作为此次需要补齐的功能。
- xgd法律页指向xingguangdie.com；ddlNew当前使用自己的隐私政策与使用支持链接，不能直接把另一个产品的协议当成本产品协议。

## 已确认方案（用户授权直接实施，保留新端DNS1）

1. 网络检测复用新端当前DNS1读取、解析和独立ECDH探测能力，补充可观察的诊断结果；不保存选点、不重连正式Socket、不写入登录状态。展示设备网络与外网可达性、主域／备域／BIN来源结果及节点探测耗时。没有运行的步骤标记未检测，不伪造成功。支持重试、离页取消及账号／企业变化隔离。
2. 不恢复旧五路、OSS Auth或公网IP采集。检测网络出口使用无账号参数的连通性请求，不把Wi-Fi已连接视为外网正常。
3. 关于我们使用本App真实图标与Bundle版本，复用现有“隐私政策”“使用支持”页面及链接。若需要独立“服务协议”，须配置本产品的真实协议地址，不能只把使用支持改名。
4. 本轮不新增Flutter，SwiftUI承载同等可见功能。

## 备选方案与取舍

完整复制xgd诊断链需要重新引入已删除的五路解析／OSS配置读取，扩大网络架构与依赖范围；只有明确要求恢复这部分时才采用。建议选择以上基于新端当前网络链路的方案。

## 验证

离线验证成功／失败／超时、DNS1来源顺序、无缓存掩盖、取消重试、旧轮次隔离与正式连接不受影响；核对两入口和返回、Bundle版本及法律页面；完整无签名iOS构建，构建环境排除sentry-cli。真实网络与设备交互另行记录，不能用编译替代。
