# 冷启动恢复移到消息页与连接状态对齐

日期：2026-11-09。状态：用户已批准并实施；离线检查与构建通过，真机验收待完成。

## 目标与确认范围

用户要求 App 启动阶段不连接 TCP，将恢复放到消息页面，并按 xgd 显示在线和重连状态。用户已选择“按推荐范围，先给设计”：调整已有账号的冷启动恢复，首次登录／注册保留现有认证流程。

启动只完成本地入口和账号缓存校验，不发 DNS/BIN、临时 TCP/ECDH 探测、正式 Socket 或 AUTH。消息页首次实际显示后触发恢复，启动等待页不再承载网络进度。连接失败不把已有账号送回邀请码页。

## 当前源码依据

- 基线：ddlNew `feature-all-5`，HEAD `28f39f8`；工作区已有首页、我的、网络检测和 Tabbar 修改，全部保留。
- `AppStartupCoordinator.restoreLocalEntry` 当前调用 `startCachedReconnect` 并等待 `waitForLoginReadiness`，随后等待 `restoreCachedSession` 的 AUTH。
- `ddlNewApp` 和 `AppSessionRouter.enterMain` 再次要求真实 AUTH；`handleAuthenticationState` 将 idle/failed 直接路由到登录。仅挪连接调用会被这些门槛拦住。
- `LoginSessionService.invalidateSession` 对暂时失败也会撤销内存用户、清理 Store；新恢复流程必须区分待恢复的本地身份与已认证的业务会话。
- `MessageView` 当前只在 AUTH 非 ready 时显示技术文案，ready 时没有在线状态。
- xgd `AppDelegate.showLocalStartupUI` 按本地身份显示 Tab／登录／入口，随后启动节点竞速；并不是由消息控制器创建正式 Socket。
- xgd `NoaSessionTopView.updateConnectStateWithType` 实际显示五类文案，忽略 attempt/maxAttempts，不显示重试上限；`AppDelegate+DB` 转发连接事件。`CandyTalkHomeViewController` 还监听网络变化，并每 20 秒探测当前节点以发现假在线。

## 方案选择

采用：本地恢复入口与网络认证分离，消息页触发，会话层持有恢复任务。用户已选择这个范围；以下细节为建议设计。

其他方案：只把等待界面换成消息页，仍由启动任务发连接，改动较少但不符合启动阶段不连接的要求；让消息 View 直接拥有 Socket 生命周期，会导致切 Tab／进入聊天取消连接，不采用。

## 本地入口与会话资格

1. 无上次入口：邀请码页，保留既有用户主动连接流程。
2. 有入口、无成对账号缓存：直接登录页；登录页出现后由现有访客连接服务准备登录，不能继续依赖启动页先连好。密码、注册、协议同意与 AUTH 成功后进入主界面的合同不变。
3. 有入口且 UID、企业与凭据成对有效：建立明确的“待恢复身份”，显示主界面，默认消息 Tab；本地资料只能用于展示，不能使 `isAuthenticated` 成真。
4. 缓存结构损坏／跨企业不匹配：按既有规则撤销无效缓存并显示登录；Keychain 暂时不可读保留磁盘数据，显示登录页的可重试提示，不伪造身份或无限留在启动页。

待恢复身份由独立恢复状态拥有，至少包含恢复 UUID、UID、企业标识、阶段。根路由根据这个显式状态允许主界面存在，不将所有 AUTH idle/failed 一概放行。退出／换号／更换企业会同步撤销它。

## 恢复任务与失败处理

- 消息页实际出现时调用幂等 ensureRecovery；任务由会话服务持有，不依附 SwiftUI `.task` 的等待寿命。重复出现、回前台、快速切 Tab 均只共享同一轮。
- 恢复使用当前 DNS1 缓存→主／备／BIN与正式 TCP/ECDH→本地租户参数→缓存 AUTH；不恢复旧五路导航或远程 systemConfig。
- 正式连接前沿用 IMConnectionCoordinator 的重试；开始 AUTH 后交给现有用户认证／SDK 重连所有者，不能同时启动访客循环和用户重连循环。
- 首次 AUTH 暂时超时／连接失败：保留待恢复身份与磁盘凭据，结束并清理本次网络尝试后按退避重新恢复；每轮先等待旧任务清理。清理产生的 idle/failed 不得让根路由闪回登录。
- 已 AUTH 后的掉线继续由原 SDK 重连，页面保留；明确的认证拒绝、踢下线／封禁才清理账号并返回登录，提示沿用既有业务文案。本地数据库／凭据写入失败单独提示并停止自动重试，不能误称网络错误或悄悄删除持久化账号。
- 所有 await、代理、网络监控和探测回调核对恢复 UUID、UID、企业及当前连接轮次；旧轮次不能重开连接、改路由或覆盖新账号状态。
- 切到首页／通讯录／我的或进入聊天不关闭已启动的恢复和长连接。后台遵循现有 SDK 生命周期，暂停新增页面探测和业务层恢复调度，回前台幂等恢复；不添加后台保活。

## 消息页状态

在现有消息页顶部增加固定状态行，保持森林绿主题与原导航。状态始终占位，避免在线时移除造成列表跳动；不重做 xgd 的头像昵称整套页头。颜色与文字共同表达，支持辅助字号和 VoiceOver。

| 条件 | 文案 | 标识 |
| --- | --- | --- |
| 网络明确不可用 | 网络不可用 | 红点 |
| 首轮 DNS／连接／ECDH／AUTH 尚在进行 | 正在连接… | 橙点 |
| 重连尝试进行中 | 重连中 | 橙点 |
| 本轮连接失败、等待退避重试 | 连接失败，正在重连 | 红点 |
| 当前身份的 AUTH 已成功且连接可用 | 在线 | 绿点 |

网络未确定时不判定离线；无网络优先于其他展示状态。TCP 接通、ECDH 成功或临时探测成功都不能单独显示在线。连接代理需区分 connecting、failed、disconnected，不能像当前实现一样全部压成同一回调。无固定次数／倒计时文案。

无网络时暂停业务层新尝试和退避计时，已有 SDK 循环沿其网络门禁处理；网络恢复后只唤醒当前连接所有者。本地数据库／凭据存储故障另显示“恢复失败，请重试”及错误反馈，允许用户主动重试或退出，不套用“正在重连”的持续网络状态。

为对齐 xgd 假在线检测，消息页在前台可见且当前 AUTH 在线时，每 20 秒探测当前正式节点，超时 3 秒，同一时间最多一次。只探测该节点，不跑网络检测整套流程。当前轮次的失败触发一次既有 SDK 重连入口，立即离开在线展示；迟到失败不得中断新连接。临时探测成功不能替代 AUTH。离页／后台停止新增探测并使在途结果失效；与已有网络质量选点共用互斥／轮次约束，不新建第二条正式重连循环。

## 数据与功能边界

用户实施后追加要求：消息页先读取并显示 SDK 本地会话缓存，离线也不等待 TCP／AUTH；连接状态独立呈现。读取使用已有库的非破坏性打开路径，不创建、恢复或删除库，也不配置 Socket／AUTH。无缓存时显示空列表；读库失败允许离线重试。同账号恢复 AUTH 与暂时失败保留列表，认证及同步成功后更新，退出／拒绝／换号仍清空。

本地身份提前显示不提前激活 ChatRuntime、来电、Push 绑定、角色权限、我的应用、会话维护或密码安全业务；这些仍在真实 AUTH 后按既有顺序启动。业务按钮受真实资格保护，待恢复期间展示明确不可用状态。推送点击继续排队等待 AUTH 和导航就绪，不丢失，也不提前进入业务。已有通知角标在真实快照未知时不置零。

首次登录／注册、邀请码录入、账号失效、退出及更换企业回归必须保留。xgd 全程只读；不改好友在线圆点，不改网络检测页面，不操作真实账号或设备，不提交／推送。

## 实施范围与验收

预计涉及 AppStartupCoordinator、ddlNewApp、AppSessionRouter、LoginSessionService、消息页恢复／状态组件、认证连接事件适配、登录页访客恢复接线及对应测试。具体文件拆分、依赖注入、事件类型命名由实施阶段决定，沿用现有 SwiftUI ObservableObject／MainActor 架构，不进行无关框架迁移。

必须先复现并验证：

1. 有效缓存冷启动至消息页出现之前，DNS、TCP 探测、正式连接与 AUTH 调用均为零；不受无限网络等待阻塞。
2. 消息页出现触发一次恢复；反复出现／切 Tab／进入子页不重复启动或取消；无账号登录页仍可正常准备与登录。
3. 首轮失败、无网络、网络恢复、AUTH 超时、连接重试与成功的状态顺序；弱网保留页面与凭据；明确账号失效返回登录。
4. AUTH 前所有在线业务门禁有效；成功后原有消息／好友同步、Push、来电、维护只激活一次。
5. 探测失败、恢复、后台／离页取消，以及旧探测／旧 AUTH／旧连接回执不能串新账号／新连接。
6. 退出／换企业／同 UID 重登使旧任务完全失效；手动登录／注册／协议同意回归。

运行 SessionRestore、Login、Network、Conversations、Notifications 等相关离线入口和新增状态时序检查，再进行无签名 iOS workspace 构建、diff 检查及匿名状态组件布局核对。实施完成更新 PROJECT_HANDOFF 与 README 中启动边界。真实冷启动耗时、弱网恢复至持续 AUTH、通知点击和真机页面效果单独待验，不将构建或临时探测当作端到端成功。
