# ddlNew 推送迁移设计（用户已确认）

## 目标与现状

用户要求将 xgd 推送迁移到 ddlNew。复用当前 Noa SDK、真实 AUTH 会话及 SwiftUI 导航，不引入新的推送服务商。

当前分支 feature-all-5。AppDelegate 只有 MMKV、Sentry、网络监听初始化；尚无 APNs 回调。已有用户工作区修改包含 aps-environment、CODE_SIGN_ENTITLEMENTS 和 remote-notification 后台模式，应保留并核对，不覆盖。设置页没有通知开关。TabbarView 实际使用 ClubStore.selectedTab 和 ActivityNavigationScope，不能把 RouterTool 的旧 NavigationPath 当作当前详情导航。登录生命周期由 LoginSessionService 所有，身份需包含租户、UID 和登录轮次。

## 方案比较

1. **推荐：完整迁移并适配现有架构。** APNs 注册绑定、在线后台本地通知、前台声音/震动、设置同步、角标、点击路由一并接入。修正 xgd 本地通知绕过开关、delegate 初始化过晚、Token 晚到未补报及群 @ 文案覆盖问题。工作量较大，但提供完整闭环。
2. 只接 APNs 注册与点击：接入较小，但缺少在线通知及设置闭环，不满足完整迁移意图。

用户已确认完整迁移并明确 xgd 项目代码不得修改；实现限定在 ddlNew。

## 行为合同

- App 启动立即设置通知中心 delegate；首次真实登录后请求系统通知权限，拒绝不阻止登录，设置页提供系统通知状态与打开系统设置入口。
- 保存 APNs Token，Token 与已认证身份任一就绪或变化时协调上报，使用旧 SDK 的 osType=1、pushServer=apns、pushToken、userUid 合同。失败可在后续登录/恢复前台/重新认证时重试，防止并发重复绑定与旧回包污染。
- 主动退出时在旧凭据失效前尝试解除绑定；本地退出不等待无限重试。撤销资格立即清理观察、待跳转、本账号本地通知和角标；失效凭据无法解除服务器绑定时如实记录限制，不用新账号身份执行旧操作。
- 设置页增加“新消息通知”“声音”“震动”，沿用 isNewMsgNotify/isVoiceNotice/isShakeNotice 服务端接口，读取失败保留本身份已知快照并可重试，保存失败回退。缓存按租户和 UID 隔离，登录轮次隔离回调。
- 前台不主动弹系统横幅，沿用一次声音/震动提醒；正在查看同一聊天时抑制提醒。后台收到在线聊天/好友申请时生成本地通知。声音与震动的独立设置针对应用内提醒；后台系统声音/震动由系统通知设置管理，不承诺后台独立控制震动。
- 本地通知统一检查通知总开关、会话免打扰、当前身份、非本人消息和消息有效性。只订阅实时接收，不把历史回读/翻译更新当作新通知；依据稳定消息 ID 去重，通知标识避免所有消息共用一个常量。消息类型摘要、好友备注、群成员显示名及群公告沿用现有数据；@我或@所有人用集合命中判定。
- 复核 SDK 自带声音调用，确保与新通知协调器只有一个应用内声音/震动所有者，避免重复提醒。具体适配方法在实现阶段依当前 SDK 调用点确定。
- 普通消息提醒不得抢占通话、录音或媒体播放的音频会话所有权；忙碌时的抑制由协调器统一执行。
- APNs payload 兼容 jumpType/chatType/sessionId/chatName；本地 payload 附加租户与接收用户归属。冷启动点击暂存，等真实 AUTH、数据库和主导航就绪后消费一次。重复点击与当前相同聊天不重复入栈；好友申请进入现有新朋友页。跨账号、跨租户或非法参数丢弃。
- 旧 APNs 若无接收者/租户字段，无法仅凭 payload 证明归属：仅在点击时有可关联的当前/待恢复身份且登录后同身份成立时尝试验证会话；没有可靠身份或资源验证失败则落消息/通讯录列表，不盲目打开详情。退出或更换身份后撤销待跳转。
- 角标复用当前会话未读与好友申请未读；页面内 Tab 角标继续沿现有逻辑。通知交付不标记消息已读；点击通过已有 ChatRoomView/ChatStore.open 进入，保留当前开页清除会话提醒及正文可见已读规则，通知模块不额外发送重复的全会话已读请求。交接中 10 月 21 日开页清未读规则取代 10 月 14 日历史限制，以当前源码为准。
- 角标等待真实未读快照，不用申请列表条数推算，也不在初始快照未知时用默认零覆盖已有系统角标；保留当前会话免打扰和手动未读计数口径。

## 实现边界

新增通知协调器、系统通知适配、SDK Token/偏好/实时消息适配、可测试的消息过滤与 payload 路由模型。接入 AppDelegate、根 scenePhase、LoginSessionService、实际 Tab 导航、设置页与可见聊天生命周期。所有异步业务回调检查完整认证上下文；保留既有启动、重连、通话、MiniApps 与补发修改。

不增加 PushKit/CallKit，不保证进程被杀后可通过 SDK 长连接收消息。离线推送依赖服务端为 com.sigua.ddlNewapp 配置正确 APNs topic、凭据和环境；客户端 entitlement 不能代替服务器配置。不读取或上传 cer 目录中的私钥材料。服务端代码/账户操作不在本次客户端迁移范围。

后台由系统直接展示的远程通知，其声音、内容及免打扰需服务端执行已保存的偏好；客户端只能控制已收到回调的场景。若服务端 payload 不含共同消息 ID，则无法承诺 APNs 与本地通知全链路严格去重，需记录实测结果和服务端补齐项。

离线回归覆盖 Token/登录先后顺序、重试与退出竞态、同 UID 新登录轮次、偏好失败回退、免打扰/本人/历史过滤、@多人顺序、冷启动待导航、账号切换、重复点击、角标清理及一次提醒。运行相关登录/会话/聊天回归与无签名 generic iOS workspace build；同步 PROJECT_HANDOFF 对应功能进度。

真机验收另列权限首次允许/拒绝、锁屏通知、杀进程 APNs、点击冷启动、单群聊/好友申请、关闭开关及退出换号。不将离线回归和构建成功描述为 APNs 已送达。不自动提交或推送。


## 实施补充

- 运输写操作通过PushRequestLane以SDK真实完成回调串行，不用更短的Swift等待超时当作服务器结束。保存/退出等待由SDK现有运输超时收口，不无限重试。底层运输失败不证明服务器完全未受理；无服务端版本协议时不能保证超时后极端迟执行的绝对顺序。
- 普通@其他人消息回退实际渲染正文；群公告还检查groupInformStatus==1。
- 本地payload含进程和登录轮次，同进程旧轮次点击拒绝；跨进程冷恢复继续验证UID/租户和真实会话。
- 好友申请hashKey仅标识用户对，因此只在5秒窗口合并重复回调，避免同一人后续重新申请永远不提醒。聊天消息继续按稳定消息ID去重。
