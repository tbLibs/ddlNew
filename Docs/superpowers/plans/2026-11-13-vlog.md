# Vlog Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for inline execution; review the complete change with a fresh reviewer.

**Goal:** Add a fifth Vlog tab with persistent photo/video works and confirmed sharing to friends/groups.
**Architecture:** Account-isolated actor repository owns media and an atomic JSON index; main-actor store rejects stale account results. SwiftUI uses native camera/photo selection, bounded thumbnails, and the existing recipient picker plus SDK upload/send.
**Tech Stack:** SwiftUI, UIKit, PhotosUI, AVKit, Foundation, existing chat SDK; no new packages.
**Spec:** Docs/superpowers/specs/2026-11-13-vlog-design.md (approved).

## Global Constraints
- iOS 16+, five tabs, default messages; retain translation work.
- No new backend, no claimed cloud sync; existing chat upload permissions remain authoritative.
- Per tenant/UID ownership, cancel old results, xcstrings zh-Hans/zh-Hant/en.
- Keep working tree changes; no commit/push or real-recipient test messages.

## Review Focus
- Missing/corrupt media/index must preserve existing user data and allow retry.
- Account switch during import/upload must not leak assets or send under a new login.
- Large images/video must not be fully decoded in the scrolling grid.
- Permission denial, unsupported media, disk-full must release temporary resources.
- Success means queued, not delivered; retry must not resend successful recipients.
