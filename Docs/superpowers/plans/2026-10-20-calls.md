# 语音与视频通话迁移实施计划

> **For agentic workers:** 使用 superpowers:subagent-driven-development 按任务实施，代码保留当前工作区，不提交或推送。

**Goal:** 依据 xgd 在 ddlNew 接通单聊、群聊语音和视频、应用内来电与完整通话页面。

**Architecture:** 新增独立 Calls 模块，用一个绑定用户、邀请码和认证轮次的 CallCoordinator 管理通话。信令复用 NoaChatCore；媒体复用已经通过 SPM 链接的 LiveKit / ZegoExpressEngine。SwiftUI 页面只消费通话快照和动作，不拥有房间连接。

**Tech Stack:** 现有 Swift 5、iOS 16、SwiftUI、Combine、UIAdapter、NoaChatCore、LiveKit、ZegoExpressEngine。

**Spec:** `Docs/CALL_MIGRATION_REQUIREMENTS_2026-10-20.md`，由产品经理对照源码维护。

## 已确认的旧端规则

- `enableAudioAndVideoCalls` 控制入口，`video_source_config` 为 `0` LiveKit、`1` Zego。
- 群 `isNetCall` 开启时普通成员不能发起，群主/管理员可发起；注销账号不能呼叫。
- 单聊直接发起；群聊先选真实成员，至少选择一名其他成员；不凭九宫格虚构人数上限。
- 群已有通话通过聊天页提示条加入，发起入口仍走选人。
- 需要处理接听、拒绝、取消、未接通、忙线、远端挂断、媒体失败、静音、扬声器、摄像头开关/切换、缩小和恢复。

## 共享 UI / 业务接口

业务开发负责以下接口和类型，页面开发只消费。需要调整时先通知主线程。

```swift
enum CallKind: Int, Sendable { case audio = 1, video = 2 }
enum CallPhase: Sendable { case outgoing, incoming, connecting, connected, ending }
struct CallParticipant: Identifiable, Equatable, Sendable {
    let id: String
    var name: String
    var avatar: String
    var isLocal: Bool
    var isConnected: Bool
    var cameraEnabled: Bool
    var microphoneEnabled: Bool
}
struct CallSession: Identifiable, Equatable, Sendable {
    let id: UUID
    var context: ChatContext
    var kind: CallKind
    var phase: CallPhase
    var title: String
    var isIncoming: Bool
    var participants: [CallParticipant]
    var connectedAt: Date?
    var microphoneEnabled: Bool
    var cameraEnabled: Bool
    var speakerEnabled: Bool
    // 业务可追加房间、供应商、邀请者及连接凭据；敏感字段不序列化。
}
struct CallSelectionRequest: Identifiable, Equatable, Sendable {
    let id: UUID
    let context: ChatContext
    let kind: CallKind
    let members: [CallParticipant]
    let selectedIDs: Set<String>
    let isAdditionalInvite: Bool
}
struct CallGroupRoom: Identifiable, Equatable, Sendable {
    let id: String // group ID
    var roomID: String
    var kind: CallKind
    var participants: [CallParticipant]
    // 业务可追加加入房间所需的非持久化属性。
}
@MainActor final class CallCoordinator: ObservableObject {
    static let shared: CallCoordinator
    @Published private(set) var session: CallSession?
    @Published var isPresented: Bool
    @Published var selection: CallSelectionRequest?
    @Published var errorMessage: String?
    @Published private(set) var busy: Bool
    @Published private(set) var groupRooms: [String: CallGroupRoom]
    func activate(userUID: String, tenantID: String, sessionID: UUID)
    func close()
    func canOfferCall(context: ChatContext) -> Bool
    func start(context: ChatContext, kind: CallKind) async
    func submitSelection(_ ids: Set<String>, requestID: UUID) async
    func cancelSelection()
    func accept() async
    func hangUp() async
    func inviteMembers() async
    func refreshGroupRoom(context: ChatContext) async
    func joinGroupRoom(context: ChatContext) async
    func toggleMicrophone()
    func toggleCamera()
    func toggleSpeaker()
    func switchCamera()
    func setForeground(_ foreground: Bool)
    func minimize()
    func restore()
}
@MainActor final class CallConfigurationStore: ObservableObject {
    static let shared: CallConfigurationStore
    func update(json: String, tenantID: String)
    func clear()
}
// SDK开发提供真实媒体画面薄桥接，不使用模拟画面。
struct CallVideoSurface: View {
    let participantID: String
    let coordinator: CallCoordinator
}
```

`CallCoordinator` 的实例构造可额外注入信令、媒体、权限和时钟，用于运行真实状态机的离线检查。`CallSession.context.route.kind == .group` 判断群通话。通话中打开成员邀请由同一全屏页面承载 selection，非通话中的发起选人由根呈现层承载，确保网络失败后原选择页仍可重试。

## Review Focus

1. 接口响应前挂断、对端结束先于本地响应、重复信令不能复活旧房间。
2. 同 UID 重登或更换邀请码后迟到回调不能接通、清理或退出新账号通话。
3. 麦克风/相机拒绝及授权期间取消不能发送邀请；来电预览不自动采集。
4. 挂断或媒体失败必须停止铃声、心跳、音视频采集、渲染和房间连接。
5. 来电可覆盖现有聊天/媒体页面，最小化后仍能恢复，后台关闭视频而恢复前台不意外开启用户手动关闭的摄像头。
