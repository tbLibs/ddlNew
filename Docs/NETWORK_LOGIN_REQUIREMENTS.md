# 网络与登录补齐需求

日期：2026-10-13。状态：本轮已授权接入，本文定义需求与验收口径；完成情况以当前源码、验证记录和真机结果为准。

## 用户价值与问题

用户输入邀请码、通过账号认证后，应能在切回 App、网络变化和长时间使用时保持可用连接，及时看到服务端最新资料及权限。用户主动退出后应释放服务端会话；账号被封禁、网络地址受限或密码需要修改时，App 应说明原因并进入对应处理流程。网络超时不应误判为账号失效，旧账号或旧邀请码的请求不能影响新会话。

当前源码已有 DNS/OSS 导航、TCP/ECDH 竞速、systemConfig 首次读取、账号登录与验证码/安全码、缓存 AUTH 恢复、登录后 TCP 节点巡检，以及真实通讯录和只读会话列表。本轮补齐七项生命周期与账号状态能力。这里的需求来自用户指定范围与旧项目源码对照，未把用户研究、线上指标或真机联调当成已完成证据。

## 范围合同

| 编号 | 本轮接入 | 交付结果 |
| --- | --- | --- |
| R1 | 回到前台检查现有长连接存活 | 对当前正式 Socket 探活，失活交给现有重连流程 |
| R2 | 定时刷新系统配置 | 前台周期更新可用配置，并隔离旧连接/旧邀请码结果 |

继续暂缓手机号/邮箱登录、验证码登录、找回密码、IP/域名直连、扫码导入导航、App 内 SOCKS5；保留邀请码入口。已存在的账号密码登录中的验证码、安全码验证继续使用。不恢复已删除的演示拉黑、演示举报，也不恢复“登录遇到问题”按钮。R6 的已登录改密属于本轮，找回密码仍暂缓。角色权限刷新只约束当前已存在的真实功能，不顺带建设真实聊天、群管理等新业务。

## 共用状态与凭据规则

1. 登录接口成功、存在本地 Token、完成 TCP/ECDH 均不能单独进入主界面。仍须 SDK 用户 AUTH ACK 成功，当前连接轮次、用户 UID、数据库归属一致。
2. 业务刷新只在当前用户 AUTH 有效且 App 前台时执行。系统配置可在前台且访客连接已就绪的登录页刷新；邀请码页、启动恢复未完成时不另开重复初始化请求。
3. 每类任务最多一轮在途。初次、定时、前台恢复触发合并；正在运行时不堆积重复请求。后台暂停周期任务，不补跑所有错过的 tick；回前台最多补一轮已到期刷新。
4. 回调写入前核对会话 generation、UID、邀请码/组织、连接或导航版本、请求序号；涉及 HTTP 请求的结果还应核对其适用的 Host。只检查 UID 不足以隔离同一账号重新登录。
5. 后台、退出、切换账号、切换邀请码、连接重建会撤销本轮结果权限。能取消的任务实际取消；SDK 无取消句柄的任务允许自行结束，但不能写缓存、换 Host、弹窗、恢复定时器或跳页面。
6. 临时断网、配置/资料/权限刷新失败、HTTP 探测全部失败、SDK 重连过程均保留有效会话凭据。明确认证拒绝、封禁、注销和强制下线才清理当前用户会话并回登录页。
7. 用户资料仍由 ObjectMapper 与 AppStorage 存储；Token、deviceSecret、记住的登录密码由现有 Keychain 分项保存。保持固定 key 与单份缓存策略，不改为按邀请码拼接持久化 key；读取会话凭据仍校验所属邀请码。
8. 日志仅记录阶段、耗时、业务码、结果及脱敏关联信息；文档与测试结果不得保存真实密码、Token、deviceSecret、加密密钥或诊断认证信息。

## R1：回到前台检查现有长连接

**场景：** 用户短暂切出 App、锁屏，或后台期间 Wi-Fi/移动网络切换后回来。系统仍可能显示 Socket 已连接，但连接实际上失活。

**行为：** 已登录用户每次从后台进入前台，都调用 SDK 的 `verifyConnectionOnForeground` 等当前正式连接探活入口。探活验证实际正在使用的 Socket；TCP 候选 ECDH 测速成功不能替代这个结果。失活由 SDK 现有断线/重连和应用连接协调器继续恢复。已在连接或重连时合并处理，避免新建第二条正式连接。

**验收：**

- 短暂后台返回也执行正式连接检查；健康连接继续使用，保留 Token、用户数据库和主界面。
- 制造后台半开连接，回前台可触发失活处理并最终恢复 AUTH；恢复后真实会话/通讯录继续同步。
- 未登录、邀请码页或启动链路正在初始化时，不发送用户探活或再次运行整套登录。
- 权限弹窗造成的 active/inactive 切换不会重复运行启动或并行探活；真实后台返回能够检查。
- 探活/重连期间退出或换账号，旧成功回调不能进入主界面。

## R2：定时刷新系统配置

**场景：** 用户不重启 App，服务端调整登录/注册开关、验证码渠道及已接入 SDK 的系统设置。

**行为：** 使用现有 systemConfig 签名、响应映射、校验、存储和 SDK 应用路径。沿用旧项目 3–8 分钟随机刷新间隔；首次 AUTH 后立即触发一轮配置、资料与权限刷新。初始化仍按现有顺序读取配置，刷新不能重新触发启动路由。

**验收：**

- 前台到期至多发起一轮刷新，完整且合法响应才替换缓存并通知现有消费者。
- 正确处理字符串、数字、布尔混合类型；缺失必需字段、业务失败或解析失败保留上一份可用配置。
- 已 AUTH 会话刷新失败不退出；登录页已有可用配置刷新失败仍可重试登录。
- 新配置不注入本轮排除的品牌动态展示或 Sentry/Logan 动态配置。
- 退出、换邀请码、HTTP Host/连接版本变化后的旧配置回调不能覆盖新上下文。

## R3：服务端退出登录

**场景：** 用户在“我的”主动退出，或更换俱乐部时结束当前用户会话。

**行为：** 当前已认证会话主动退出时，携带旧会话快照调用 SDK 的 `authUserLogoutWith`（`/auth/account/outLogin`），在撤销 SDK 用户凭据前使请求使用正确账号和设备上下文。立即撤销业务任务写权限，有界等待服务端退出结果后完成本地用户、凭据、数据库运行时与页面状态清理；到期、离线或失败仍完成本地退出。

**验收：**

- 正常退出可观测到服务端请求，并清理本地当前会话；普通退出保留邀请码入口，返回登录页。
- 更换俱乐部清除可恢复入口和当前会话，返回邀请码页；退出请求使用旧俱乐部/旧用户上下文。
- 离线、超时或服务端失败也能完成本地退出；不展示“服务端退出成功”的虚假结果。
- 连续点击退出只触发一次；未认证访客不调用用户退出接口。
- 已完成退出后旧成功/失败回调不恢复会话，也不清理随后登录的新账号。
- 封禁或服务端强制下线直接走失效清理，避免反复调用退出接口产生循环。

## R4：特殊错误与强制下线

**场景：** 账号密码登录、缓存 AUTH、Token 刷新或使用过程中被服务端拒绝。

| 服务端语义 | 旧项目业务码 | SDK 强制下线类型 | 用户可见结果 |
| --- | --- | --- | --- |
| 账号封禁 | `40015` | `2` | 提示账号已被封禁，回登录页 |
| 设备封禁 | `40029` | `11` | 提示当前设备已被封禁，回登录页 |
| IP 封禁 | `40030` | `10` | 提示当前网络地址已被封禁，回登录页 |
| IP 不在白名单 | `90018` | `90018` | 提示登录 IP 不在白名单；有合法服务端 IP 内容时展示 |
| 账号信息变化 | 按实际协议映射 | `13` | 提示账号信息已变化，请重新登录 |
| 用户已注销 | 按实际协议映射 | `888` | 提示用户已注销，回登录页 |
| 其他明确强制下线 | 按实际协议映射 | 如 `999` | 提示会话已失效，请重新登录 |

**行为：** SDK 下线类型与原始业务码分别映射，不能把 `2` 当作 HTTP 业务码。先撤销并清理受影响会话，再在登录页呈现一次对应原因；后台接收失效事件可立即撤销会话，提示留到前台。服务端空消息使用本地明确文案；网络超时码 `0`、SDK 临时连接认证超时/中断不能映射为账号密码错误或封禁。

**验收：**

- 六类特殊状态可分别验证正确文案和路由，普通账号密码/验证码/安全码错误继续走已有处理。
- 重复 SDK 事件、HTTP 与 TCP 同时失败时，只清理一次且只提示一次。
- IP 白名单错误保留服务端提供的安全可展示 IP 信息，缺失时不用空字符串拼成误导提示。
- 旧账号失效事件不能退出新账号；封禁回调不被普通“刷新失败”处理吞掉。
- SDK 明确认证失效删除当前会话凭据；临时断线恢复仍保留凭据。

## R5：独立 HTTP 节点测速排序

**场景：** TCP 连接可用，但 HTTP API、文件或上传链路存在慢节点，需要依据 HTTP 本身的探测结果选择候选。

**行为：** 从当前导航取 HTTP 候选，归一化、去重后使用独立 HTTP 请求测时。旧项目探测路径为 `/zlcpig`，单次超时 2 秒；间隔来自导航 `ping_interval_second`，无有效值时 300 秒。沿用成功次数优先、累计成功耗时其次的排序语义，并记录本轮可用状态。采用单调时钟和小数耗时，不把失败、取消、协议错误算作零耗时成功；只有符合探测接口响应约定的结果算成功。

**验收：**

- HTTP 排名不借用 TCP/ECDH RTT，也不触发 TCP 正式连接切换；现有 TCP 巡检继续按自身开关和策略运行。
- 本轮成功候选优先于失败候选；成功次数降序、成功耗时升序，同分保持稳定顺序。
- 各候选超时或失败均能结算本轮；全失败保留当前 HTTP Host，下一周期可重试。
- 优选结果通过现有 Host 更新入口应用，API/文件/上传 Host 一致变化；图片 URL 可随 Host 重新生成。
- SDK 下发 HTTP Host 与应用测速结果共用同一状态入口；切换后的旧请求不把 Host 改回。
- 后台/退出/换邀请码取消探测；旧排名不得进入新导航，也不得在后台恢复计时器。

## R6：弱密码检查与强制改密

**场景：** 密码与账号相同、属于弱密码，或服务端要求用户改密后继续使用。

**行为：** AUTH 成功后对当前用户调用 SDK 密码强度检查。账号密码登录可使用仅本轮持有的密码获取一次性 encryptKey，并按现有加密方式提交；缓存 AUTH 恢复无原始密码时按 UID 查询，不能为了检查强度自动重放密码登录。按响应 `isWeakPassword`、`type`、`roleConfigMap.forcedPasswordReset` 判断；类型兼容 `PASSWORD_EQ_ACCOUNT`、`WEAK_PASSWORD` 及未知类型的通用安全提示。

**验收：**

- 非弱密码正常继续；非强制弱密码提供“去修改”和“稍后”，本次会话不重复弹窗。
- 服务端确认强制改密后，主界面业务操作不可用；不提供跳过，关闭弹层、返回按钮、交互返回、重启或后台恢复均不能绕过。允许用户退出会话。
- 使用真实旧密码验证/修改密码接口；输入不一致、格式错误、旧密码错误、超时等展示可操作提示，提交期间防止重复点击。
- 仅服务端改密成功后完成本次强制改密；沿用旧端退出登录，清理旧会话并回登录页，不假设服务端会返回新 Token。用户重新登录且新的 AUTH 成功后才能进入主界面。
- 改密成功同步处理记住密码项：更新为新密码或删除旧密码，不能下次自动填充已失效密码；不记录明文密码。
- 已确认强制改密的请求失败仍保留阻断与重试入口；首次检查临时失败允许继续，但不能标记为“强度合格”，恢复前台或下一轮刷新重试。
- 退出、换账号、换邀请码后销毁密码临时值及改密状态，旧检查/改密回调不能解除新账号限制。

## R7：用户资料与角色权限刷新

**场景：** 用户昵称/头像/角色被后台修改；已有功能权限变化需要及时生效。

**行为：** 首次 AUTH 成功后立即刷新当前用户资料与角色权限；前台按 3–8 分钟随机周期刷新，回前台到期时补一轮。复用 SDK `getUserInfoWith`、`userGetRoleAuthorityListWith` 等已有请求，按 UID 校验后更新用户资料及独立角色权限状态。修改昵称/头像等资料时保留 Token、deviceSecret 和会话所属邀请码，不用部分资料响应覆盖认证凭据。

**验收：**

- AUTH 前不发送用户资料或角色权限请求；AUTH 后首次、周期、前台恢复触发均有去重。
- 昵称、头像、账号展示等已有页面随真实资料变化；资料成功与权限成功独立应用，单项失败保留其上一次有效值。
- 当前只读会话列表按服务端文件助手权限过滤；关闭后入口、角标与列表口径一致，重新开启后可恢复真实缓存会话。
- 其他权限供当前已有功能消费，未知字段不自动开放功能；字段缺失采用明确兼容默认值，不能把解析失败当作允许。
- 退出清理权限运行时；账号 B 从不展示账号 A 权限，账号 A 的迟到回调不能更新 B。
- 普通刷新失败不退出；刷新触发明确封禁/认证失效则统一走 R4。

## 异常与生命周期验收矩阵

| 条件 | 必须产生的结果 |
| --- | --- |
| 临时断网/SDK 正在重连 | 主界面保留、凭据保留；业务定时刷新暂停或等连接就绪 |
| 回前台仍有健康正式连接 | 正式 Socket 探活；合并到期刷新，避免重跑 DNS/OSS/账号登录 |
| App 后台期间普通请求返回 | 结果作废，不写状态、不发起新请求；前台按到期策略重试 |
| App 后台期间收到明确封禁/强制下线 | 撤销当前会话；回前台呈现登录页与原因 |
| A 请求未结束，退出后登录 B | A 的资料、权限、改密、Host、配置、退出回调不能修改 B |
| 同一 UID 退出后重新登录 | 旧 generation 回调作废，即使 UID 相同 |
| 更换邀请码/俱乐部 | 清理入口及会话；旧租户配置、排名、权限与强制改密状态作废 |
| HTTP 优选与 SDK 更新 Host 同时发生 | 统一版本协调；最新合法上下文生效，旧结果不回滚 Host |
| 初始化/定时/前台事件同时触发 | 每类请求最多一轮；不叠加定时器或新建第二条正式 Socket |

## 实施顺序、责任与完成标准

本轮产品负责人：Alex；实现负责人：本次接入的 Codex 工程协调者；真机联调负责人：项目维护者。时间范围为本轮接入交付，真机依赖项在本轮交接中逐项保留状态，不虚构发布日期。

| 顺序 | 实施内容 | 进入下一步的验收门槛 |
| --- | --- | --- |
| 1 | 共用 generation/请求去重与生命周期；R4 特殊错误 | 退出与旧回调隔离可验证，临时失败不误删凭据 |
| 2 | R1 正式连接前台探活、R3 服务端退出 | 不重复连接，在线/离线退出均清理本地 |
| 3 | R2 配置刷新、R7 资料/权限刷新 | 前后台定时控制、失败保留、AUTH 门槛成立 |
| 4 | R5 HTTP 独立测速与 Host 协调 | HTTP/TCP 互不替代，全失败和并发 Host 更新可验证 |
| 5 | R6 弱密码与真实强制改密 | 阻断不可绕过、改密成功与凭据处理成立 |
| 6 | 集成构建与真机联调 | 下列清单有证据，未完成项明确记录 |

离线验证重点是迟到回调、退出、同 UID 重登、轮次去重、排序失败口径与强制改密状态；通过项目现有相关检查和无签名真机目标构建后再进入真机联调。纯文档新增不代表七项实现或联调通过。实现方同步更新 `PROJECT_HANDOFF.md` 的登录、网络、验证与进度章节。
