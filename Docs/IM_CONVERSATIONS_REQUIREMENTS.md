# 消息会话列表需求分析（旧项目对照）

本文件以 `/Users/taobotaobo/Desktop/ddl/NoaChatKit/CandyTalk/Tab/CandyTalkHomeViewController.m`、`Modules/Session/Views/NoaSessionCell.m` 和当前仓库的 `NoaChatSDKCore` 为依据。旧代码用于确认业务行为，当前仓库源码与运行结果决定实现边界。

## 目标和分期

消息 Tab 应展示当前登录账号的真实 IM 会话，并与 SDK 的同步、缓存、未读状态一致。先交付可核对的 P0 只读列表，再打开真实聊天入口及操作；任何入口都不应修改 `ClubCommunity` 的演示数据来模拟 SDK 状态。

| 阶段 | 需求 | 当前状态 |

| P0 | 从 SDK 会话库显示单聊、群聊、群发助手、群助手、签到提醒、支付助手；展示头像、名称、最近消息、时间、未读、置顶、免打扰、草稿 | 已接只读列表；支付助手沿用 SDK 类型，旧首页未见完整跳转 |

| P0 | 置顶优先，组内按最近消息时间倒序，ID 去重；Tab 角标取真实未读 | 已接 |

## 会话行与排序

旧项目的 `NoaSessionCell` 在行上展示头像、名称、最后时间、消息预览、未读数或红点，草稿优先于最后消息。免打扰会话仍可有行内未读提示，但不进入总角标。最近消息若不在会话模型内存字段，须从 SDK 消息表取回；服务器同步提供的最新消息需写入消息表，避免缓存恢复时预览消失。当前 P0 对文本、图片、视频、语音、文件、位置、名片、@、公告、表情、合并转发、通话、系统通知提供基本预览文案；复杂系统消息文案需后续逐类型对照旧项目。

SDK 数据库的完整列表按最近消息时间排序，但不按置顶分组，也不自动过滤 `sessionStatus == 0`。展示层应只取可展示状态与已知类型，按会话 ID 去重，再置顶优先、组内按最近消息时间降序。旧项目会根据服务端角色权限决定文件助手 `100002` 是否出现；当前 P0 尚未接该配置，不能将本地固定开关当成服务端权限。

## 数据与生命周期

SDK `cimToolSessionListUpdateWith` 分页回调早于异步数据库写入，`imSdkSessionSyncFinish` 在最后一页落库后触发。因此，分页回调不能作为已持久化的完整列表。P0 在 AUTH 前注册 `NoaToolSessionDelegate`，AUTH 后读取缓存，完成回调再读一遍；SDK 自动发起初次及重连同步，页面显示不重复发起服务端同步。会话变更、删除、未读变化触发合并重读；同步失败时保留已缓存的会话并显示错误。退出/切账号必须移除代理、清空 UI 状态，并以账号 UID 与轮次阻断迟到回调。

未读总数按 SDK 口径：正常会话累加 `sessionUnreadCount`，手动标记未读的 `readTag` 额外计 1，免打扰会话不计入 Tab 角标。P1 操作需要同时核对本地 SDK 模型和服务端请求结果，尤其是“标记未读”与真实未读消息数的区别。

## 入口与操作规则

旧首页的单聊和群聊进入不同聊天上下文；文件助手是特殊单聊 ID `100002`；群发助手、群助手、签到提醒各有独立页面。单聊/群聊点击后会处理已读、清理本地计数和记录最新已读服务端消息 ID。P1 必须先完成真实消息页与读回执，才开放列表行点击，否则用户会看到演示聊天或被错误清除未读。

旧首页的普通单聊/群聊提供置顶、免打扰、标记未读/清除未读、删除等滑动操作；特殊助手限制可执行操作，不能把通用操作直接复用到每个类型。删除会话和清空聊天记录是两个独立动作，旧列表删除默认保留消息记录。操作失败时应恢复列表与角标，并显示可理解的错误。

## 验收场景

1. A 账号有会话、B 账号无会话：退出 A 后 B 不出现 A 的行、头像、预览和角标；A 的迟到同步不污染 B。
2. 首次同步跨多页：分页过程中可显示旧缓存，同步完成后无遗漏、重复或顺序跳动残留；无网络时展示缓存与失败提示。
3. 置顶旧会话排在普通新会话前；置顶组与普通组内部都按最近时间倒序。
4. 免打扰行可显示未读提示，但总角标不计；`readTag == 1` 且真实未读为 0 时显示未读红点并计 1。
5. 收到新消息、会话删除或被其他端标记已读后，列表与 Tab 角标随 SDK 更新；重启缓存恢复仍有最近消息预览。
6. P0 行不可进入演示聊天，也不产生本地假已读；P1 上线后再验证点击、读回执、服务端失败回滚和不同会话类型的操作权限。

## 验证限制

无签名 iOS 构建与本地排序/角标校验只证明代码可编译及纯逻辑正确。登录、SDK 服务端分页、重连、跨设备已读与切账号的端到端行为仍需使用可完成系统配置签名和 AUTH 的真机账号验证。
