# 登录验证与连接恢复实施记录

**目标：** 按 xgd 协议补齐邀请码导航兜底、登录后节点切换、验证码和安全码验证。

**结构：** 登录前初始化与登录后重连分别管理。登录服务通过异步弹窗等待用户验证，密码、临时加密密钥和安全码挑战标识不进入页面状态。

**范围：** 仅使用邀请码入口；沿用 AUTH、会话存储及记住密码流程；保留用户现有 Xcode 项目改动。

## 已完成

- [x] 网络：缓存 TCP 候选竞速失败后刷新邀请码导航，接入 SDK 重连与取消回调，保留已登录用户。
- [x] 导航：五路 DNS 后接旧解析器、缓存及内置地址、加密 OSS HTTP 配置；校验节点后才接受结果。
- [x] 登录：图形、腾讯、阿里验证码与安全码分流；每次提交领取新加密密钥，拒绝旧连接结果。
- [x] 页面：可取消的验证弹窗、验证码网页资源、来源校验、超时和加载失败重试。
- [x] 生命周期：认证配置后安装重连桥接，清理会话前撤销竞速；弹窗通过请求 ID 隔离。
- [x] 验证：登录检查 25/25，通过网络恢复及弹窗检查，通过设备 SDK 编译。

## 重点边界

- 取消、更换账号或俱乐部以及迟到回调不得继续旧登录或重连。
- 图形验证码降级同步切换请求渠道；结束后恢复原渠道。
- 安全码挑战标识不出现在提示或日志中。
- 空配置、畸形节点或单节点异常不能阻止有效候选获胜。
- 缓存长列表不能挤掉内置兜底地址；旧弹窗退出不能取消新验证。
- 所有新增流程注释使用中文。
