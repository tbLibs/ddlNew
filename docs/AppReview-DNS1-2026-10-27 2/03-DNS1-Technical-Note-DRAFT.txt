ENCODING AND PAYLOAD SCOPE
AAAA records are a custom data carrier. Each 16-byte record contains a two-byte big-endian fragment index and fourteen payload bytes. The implementation validates/reorders fragments and decodes UTF-8 text up to the first null byte. This is not ordinary DNS address resolution alone.
The decoded DNS text accepts a JSON object containing tcp/http, or a comma-separated TCP node list. BIN decryption accepts a JSON object with a required tcp array and an optional http array. The BIN path supports binary ciphertext or its Base64 representation. Its helper uses the existing AES-128/ECB/padding protocol; see the source appendix for exact derivation and implementation. This note does not claim the encryption hides code or provides a separate integrity guarantee.

tcp: an array of server host:port strings; bracketed IPv6 is supported. At least one valid TCP node is required. It supplies messaging connection candidates.
http: an optional array of HTTP or HTTPS service URLs. Scheme/path may be preserved. The first valid URL supplies the API/file download host; the upload host appends /oss. It is not solely a TCP discovery protocol.
Additional JSON fields are ignored by this parser; the implementation does not reject all unknown fields. Parsed values are endpoint data, not executable instructions. This describes the DNS1 path, not an audit certification of every other app component.

LOOKUP AUTHENTICATION
The query includes name, type=AAAA, uid, ak, ts and key. key is a SHA-256 signature calculated from the account ID, secret, timestamp, domain and access key in the order visible in DNS1DoHClient. The secret is not directly sent as a query parameter. Production credential values and signed request URLs are excluded from this attachment.
